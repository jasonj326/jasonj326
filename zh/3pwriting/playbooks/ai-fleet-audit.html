會頂嘴的夥伴——我的八人 AI 艦隊，和一場五個月的自我審計

一個天真的問題

朋友看到我同時在弄個人網站、跨境法律實務、一個上了以太坊主網的感謝計畫、一個 Telegram 行為教練 bot、一個知識庫、每天直播，問我：「你一個人怎麼做這麼多？」

我不是一個人。我有八個同事。他們是 AI，但不是那種你問一句答一句的 AI——他們有名字、有職掌、有交接文件，而且會頂嘴。

艦隊點名

每個 session 是一個獨立的 Claude Code 工作區，有自己的記憶、自己的工程日誌、自己的地盤：

  • Webb：管我的網站 jasonjlai.net，含種子牆和一個叫 Lia 的公開 chatbot
  • Lex：法律副手——合約審查、法規追蹤、教學講義
  • Forge：PIF12 智能合約與領取網站（2026 年 6 月上主網）
  • Coach：Telegram 行為教練，管我的習慣和任務
  • Bard：直播日記與溝通技藝
  • Poly：知識編譯器，把書和課程拆進我的 wiki
  • Scout：職涯偵察，掃職缺、備申請
  • 還有一位試用期的 Neo，整理我的個人資訊流

沒有「總管」。曾經有過一位協調者（CLia），三個月後我把這個角色廢了——AI 之間跟人類組織一樣，多一層中介就多一層失真。現在是 P2P：一份共用的交接檔（HANDOFF.md），誰做完事就更新自己的區塊，開工前先讀別人留了什麼。

每一條規則背後，都有一次失敗

這套系統最值錢的部分不是架構圖，是規則——而每一條規則背後都有一次真實的災難：

備份程序本身毀了資料。 某天 Webb 照著自己寫的備份 SOP 操作，一個 git checkout 把六週的工程日誌蓋掉，七篇紀錄永久消失。事後規則改成安全的底層指令——但更深的教訓在後面（見審計那段）。

模型退役讓 chatbot 靜默死了六天。 網站上的 Lia 綁死了一個有日期的模型版本，那個版本退役後 API 回 404，程式又把 404 包裝成普通錯誤——沒有警報，服務無聲死亡。現在的鐵律：部署中的服務永遠用 alias、不釘死版本，而且不准吞掉上游錯誤。

AI 會一本正經地捏造。 法律研究裡出現過驗證不了的引用（其中一條追到源頭是某部落格的杜撰）；求職信裡出現過不存在的聯絡人。解法不是「提醒 AI 要誠實」——是讓另一批 AI 專門負責反駁：每一份含人名、數字、引用的交付物，先過一輪「盡力證明這是錯的」的對抗驗證，才輪得到我看。這套流程至今抓到六次，包括一次差點上線的網站漏洞。

五個月的自我審計

今年七月，我做了一件有點後設的事：讓艦隊審計自己。十七個唯讀 agent 平行翻遍五個月的 git 歷史、工程日誌、對話紀錄，交叉比對「文件說的」和「檔案系統實際的樣子」。

最大的發現只有一句話：教訓不會自己複利。

我們的工程日誌是世界級的——每次失敗都被誠實記錄、每個根因都有分析。但設定檔幾乎什麼都沒學到。同一個坑（某個 Python 路徑問題、某條格式規則、日期算錯）在不同 session 被重複踩，因為「教訓」只住在日誌裡，沒有變成規則、腳本、或自動護欄。寫下來，不等於學會了。

第二個發現同樣扎心：九份專案說明文件，九份全部與現實脫節。最危險的一份還寫著舊的區塊鏈，而合約早已在另一條鏈上線。文件是快照，現實在跑——沒有機制逼它們同步。

把願望變成機械

審計之後的升級，一句話總結：規則沒有 enforcement 就是願望。

  • 那個毀過日誌的指令？現在有一支 hook 直接攔截它——不靠任何人「記得」。
  • 每個 session 開工時，系統自動注入今天的日期和 git 狀態——治好長 session 的「今天是幾號」錯亂。
  • 重複解釋了二十次的工作流程，變成一鍵指令：/wrap 收工儀式、/verify-facts 對抗驗證、發文、部署、轉錄，各就各位。
  • 收工儀式裡加了一道閘門：任何踩過兩次的坑，當天就要變成規則或腳本，否則要白紙黑字寫「我決定不處理」。

如果你只帶走三件事

  1. 寫日誌不等於學習。 學習發生在教訓變成「下次不可能再犯」的機制那一刻——一條 lint、一支 hook、一個 checklist。問自己：上次的教訓，現在住在哪裡？
  2. 讓 AI 互相反駁。 對任何要出門的東西（人名、數字、引用），叫第二個 AI 用力證明它是錯的。信任來自對抗，不來自語氣誠懇。
  3. 規則從失敗長出來，不從模板抄來。 我的每條規則都指向一次真實的痛。從你自己的第一次災難開始寫第一條規則，它會比任何最佳實踐清單都管用。

這些都在線上
